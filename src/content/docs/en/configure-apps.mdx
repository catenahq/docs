Catena manages an app from labels written in its compose file: it publishes the address, puts the sign-in gate in front, backs up the data, updates the app and watches it on the status page. When the software is in Catena's catalog, the catalog entry is the shorter route: its labels, networks, placement and sign-in client are already in place.

## Add an app from a repository

Administrators add apps with **Add an application**, above the cards of the **Apps** page, and configure them from each app's page, opened with the gear on its card. Each app lives in its own folder, which is in every backup and runs the app without Catena (see [Restore one app on any machine](/en/features/backup-restore-migrate/#restore-one-app-on-any-machine)).

An app comes from a git repository on the server's list; Catena's catalog is on it from the start. To add an app:

1. Open **Apps** and press **Add an application**.
2. Choose the **Repository**, enter the **Application** name and press **Show versions**. After you publish a new app or version, press **Read again** to read the repository's list at once.
3. Choose a **Version**: a tag the repository published for the app.
4. Optionally enter **Name on this server**: lower-case letters, digits and hyphens.
5. Press **Add**.

Catena fetches the app at that version, checks its compose file (see [Check an app with the panel](#check-an-app-with-the-panel)) and leaves the app stopped; a file with an error is refused.

Press the gear on the app's card, enter its settings (see [Settings, deploy, take down and delete](#settings-deploy-take-down-and-delete)), then press **Deploy application** in **Overview**. The app reads **Starting** until it has answered its ready question (see [Declare the backup mode and update steps](#declare-the-backup-mode-and-update-steps-optional)).

### Settings, deploy, take down and delete

Each app has a page of its own. The **On this page** card opens one part at a time:

- **Overview.** **Deploy application** (**Redeploy application** while the app runs) deploys the settings file and the compose file as they are. **Take down application** removes the app's services and keeps its data, files and settings. **Delete application and data**, on while the app is down, erases the app and all its data, after the page says the date of the latest backup that holds the app (see [Restore](/en/features/backup-restore-migrate/)); when no backup holds it, the page warns that nothing can bring it back and asks you to type the app's name.
- **Settings.** **Open the settings** shows the app's settings file, every value as the file holds it. **Save the settings file** deploys nothing: **Redeploy application** applies it to a running app, and an app that is down takes it at its next deploy. After the app's first start, a generated value that the app keeps its own copy of asks for a confirmation tick: change the app's copy first. A value the app takes only before its first start, such as the folder it keeps its files in (see [Keep an application's files on a disk you attach](/en/configuration/backups/#keep-an-applications-files-on-a-disk-you-attach)), is locked once the app has run. A line that Catena writes itself cannot be changed.
- **Logs.** The newest lines of each service, in a console (see [Consoles](/en/features/admin-dashboard/#consoles)).
- **Vulnerabilities.** What the vulnerability watch found (see [Vulnerabilities page](/en/configuration/vulnerabilities/#vulnerabilities-page)).
- **Update.** **Version** chooses the version before the first start; after it, the update on offer shows here (see [updates](/en/configuration/updates/#apps-added-from-a-repository) and [Apps changed outside Catena](/en/configuration/updates/#apps-changed-outside-catena)).

### Changes that run together

Changes to two apps run at the same time. A change waits for another change to the same app and for the apps that use a service it provides. A task on the whole server (a configuration run, a restore, the maintenance, an update) goes first: it waits for every running change, and other changes wait for it.

### Repositories

**Repositories**, under **Manage applications**, lists the repositories you can add apps from. Enter the **Repository address** (an `https://` address with no password, query or fragment) and, for a private repository, an **Access token**. Tick **Trusted: apply its updates by themselves** only for a repository whose author you trust, then press **Save repository**.

A repository holds `blueprints/<app>/docker-compose.yml` with the app's other files beside it, at most 500 files and 5 MiB, with no link or submodule. It publishes each version as a tag spelled `<app>/<version>-<revision>`, such as `my-app/1.2.3-1`, where the version and the revision use letters, digits and the characters `.`, `_`, `+` and `-`.

Only a file of Catena's catalog may give an app the server's network or the container engine, and only those its `x-catena` block declares, whether you changed the file by hand or not. Only an unchanged file of Catena's catalog may read stored secrets or take values that another app provides; any other file that asks for them is refused.

### What an app can ask of Catena

The `x-catena` block of an app can declare what it needs of the server: Catena fulfils it before each deploy, with a certificate for the app's names and DNS records in the zones the server serves. An app can also provide a service to other apps, which the apps that use it find by themselves.

## How Catena reads an app

An app is a set of services. One of them, the **front-door service**, answers the web requests; the others (database, cache, background workers) are internal and stay out of reach of the internet and of other apps. You write labels under each service's own `labels:` key, as a list with one `"key=value"` per line; labels under `deploy.labels` are not seen.

A service that carries `vps.route.host` has a public **address**, and its port, who gets in and health check are read from that service alone. With two or more addresses, you mark the **main address** with `vps.route.main=true` on its service; the labels that describe the app as a whole (its tile, its status-page title, its sign-in entry, `vps.auth.protected`) are read from that service only. Access is set per address and never inherited from the main address. ## Sign in with Catena accounts (optional)

An app that supports OpenID Connect can let people sign in with their Catena account. On the front-door service, add the `vps.auth.oidc` labels (see the [label reference](#on-the-front-door-service-once)) with the app's callback address, such as `https://my-app.yourdomain.com/auth/callback`: it is `https://` on a domain this server serves, or a phone app's own scheme. A `*`, plain `http://` or a `#` is refused, and when a label is wrong, Catena makes and changes nothing for that app.

In the compose file, pass the values to the app with an empty default: `${OIDC_CLIENT_ID:-}`, `${OIDC_CLIENT_SECRET:-}` (absent for a public app) and `${OIDC_ISSUER_URL:-}`. Within a few minutes of the deploy, Catena creates the entry in Keycloak and writes the values into the app's settings. The tile shows **sign-in ready**, **sign-in waiting** or **sign-in failed**, with the reason (see [Single sign-on](/en/features/single-sign-on/)).

## Label reference

### On each service with an address

| Label | Values | Description |
|---|---|---|
| `vps.route.host` | An address under `yourdomain.com` | Public address. Without it on any service, the app has no route, no tile and no status-page card. |
| `vps.route.port` | A port number | Default `80`. Port the service listens on inside its container. |
| `vps.auth.mode` | `public`, `private`, `admin-only` | `private`: the groups in `vps.auth.groups`, or `admin`, `client` and `staff` when none are listed. |
| `vps.auth.groups` | Keycloak group names, comma-separated | Groups allowed in. Ignored with `public` and `admin-only`. The group `visitor` makes the address public. |
| `vps.auth.public_paths` | Paths, comma-separated, each starting with `/` | On an address behind sign-in, these exact paths open to everyone. At most 8. `/` and a path under `/oauth2` stay behind the sign-in. |
| `vps.health.path` | A URL path | The address is up when this path answers 200; without it, the front page is checked. |
| `vps.health.expect` | Text | Text the reply must contain. Used only with `vps.health.path`. |

With neither `vps.auth.mode` nor `vps.auth.groups`, only administrators get in. The mode can come from a setting: `vps.auth.mode=${AUTH_MODE:-public}`. Putting an app that signs in by itself behind the sign-in gate also limits its own sign-in to the groups the gate admits, and its mobile and desktop apps may stop connecting.

### On the front-door service, once

On the main address's service only; on any other service these labels are ignored.

| Label | Values | Description |
|---|---|---|
| `vps.route.main` | `true`, `false` | Default `false`. Marks the main address, on exactly one service. Needed only with two or more addresses. |
| `vps.auth.protected` | `true`, `false` | Default `false`. Marks an app that must not be public: administrators see a badge when its labels make it public anyway. |
| `vps.auth.oidc` | `true`, `false` | Default `false`. Catena creates the app's sign-in entry in Keycloak and puts `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET` and `OIDC_ISSUER_URL` in the app's settings. |
| `vps.auth.oidc.redirect_uris` | Addresses, comma-separated | Return addresses. Required with `vps.auth.oidc`. |
| `vps.auth.oidc.public` | `true`, `false` | Default `false`. For an app that sends no secret: the entry requires PKCE. |
| `vps.display-name` | Text | Default the main address. Title of the status-page card. |
| `vps.homepage.name` | Text | Default the app's name on the server. Title of the tile. The **Name** field of the app's page replaces it. |
| `vps.homepage.icon` | An icon name, or an image address | Default `mdi-application`. Tile icon. An address starting with `http` is shown as an image. |
| `vps.homepage.description`, `vps.homepage.description-fr` | Text | Tile subtitle, at most 300 characters; the second when the panel is in French. |
| `vps.homepage.hidden` | `true`, `false` | Default `false`. Hides the tile from everyone except administrators. |

The logo of the app's card is `logo.png` or `logo.svg` beside the compose file, in `blueprints/<app>/`: a PNG at most 512 pixels a side, either kind at most 64 KiB.

### Updates

| Label | Values | Description |
|---|---|---|
| `vps.auto-update` | `off`, `patch`, `minor`, `patch+minor`, `major` | Default `patch`. How far the image's version may move: `patch` keeps the major and minor numbers, `minor` and `patch+minor` keep the major number, `major` takes any newer release, `off` never moves it. An invalid value counts as `patch`. |

A value may read a setting, with a default: `vps.auto-update=${UPDATE_LEVEL:-major}`. Services that run the same image move together, under the most restrictive of their labels. The updates run in the maintenance, which needs Catena Pro or Catena Business ([editions](https://catena.run/en/#pricing)); see [Updates](/en/configuration/updates/).

### Published ports

| Label | Values | Description |
|---|---|---|
| `vps.expose.tcp`, `vps.expose.udp` | Ports or ranges, comma-separated | Opens these TCP or UDP ports in the server's firewall. The service publishes them itself, in long form with `mode: host`. An entry that overlaps a port the server declares itself is ignored. |

## Check an app with the panel

The **Compose checker** reads a compose file the way Docker Swarm and your server will, before you deploy it. Only administrators see it.

1. Open **Apps**, then **Compose checker** in the menu at the right.
2. Enter the **App name**, paste the compose file in **Compose file** and select **Check**.
3. Read the findings: each carries its level, its rule and what to change. **What this means** opens the rule in the lists below.
4. When corrections apply, copy the **Corrected file** into the app's file in your repository and publish a new version.

A finding is an **error** when the deploy fails, data is lost, the app cannot be reached or it gets control of the server, a **warning** when a setting does not do what the file says, and a **note** otherwise.

### What Docker Swarm refuses or ignores

| Rule | Level | What it reports |
|---|---|---|
| <a id="s0"></a>S0 | error | The file is not valid YAML, is not a compose file, has no services, or has a service that is not a set of keys. |
| <a id="s1"></a>S1 | error | A key that makes Swarm refuse the whole file: `mem_limit`, `memswap_limit`, `cpus`, `cpu_shares`, `volumes_from`, `profiles`, `scale`. Limits move to `deploy.resources.limits`, the replica count to `deploy.replicas`. |
| <a id="s2"></a>S2 | warning | A key that Swarm ignores, such as `depends_on`, `restart`, `container_name`, `expose`, `links`, `build`, `network_mode`, the short `tmpfs`. |
| <a id="s3"></a>S3 | error | A port published through the routing mesh, which replaces each visitor's address. Use `mode: host`. |
| <a id="s4"></a>S4 | error | A `configs` entry that takes its content from a file or inline text. Only `external: true` configs are accepted. |

### What Catena reads from the file

| Rule | Level | What it reports |
|---|---|---|
| <a id="k1"></a>K1 | error | A service with an address is not on `catena-network`, or the file does not declare it with `external: true`. |
| <a id="k2"></a>K2 | error | A service that stores data in a volume is not pinned to the data node. Applies from two nodes. |
| <a id="k3"></a>K3 | error | Several addresses and not exactly one `vps.route.main=true`, or two services with the same address. |
| <a id="k4"></a>K4 | warning | An app-wide label on a service other than the main address, or an address label on a service with no address. |
| <a id="k5"></a>K5 | warning | A `vps.*` label under `deploy.labels`, where Catena does not read it. |
| <a id="k6"></a>K6 | note | A public address with no `vps.health.path`. |
| <a id="k7"></a>K7 | warning, error | A warning for an access label with no effect: an unknown `vps.auth.mode`, `vps.auth.groups` on a public or admin-only address, `visitor` beside other groups, an unknown Keycloak group, or `vps.auth.public_paths` on a public address. An error for an inexact path, or more than 8. |
| <a id="k8"></a>K8 | note | An image tag with no full version, or an invalid `vps.auto-update` value. |
| <a id="k9"></a>K9 | error | A bind mount outside the apps area that is not listed under **Other folders to back up**: the backup fails. |
| <a id="k10"></a>K10 | warning | The file matches a catalog app but is deployed under another name: catalog actions and restores do not find it. |
| <a id="k11"></a>K11 | note | A `vps.*` label Catena does not read, such as one that names the app or the service. |
| <a id="k12"></a>K12 | warning | A published port that no `vps.expose.tcp` or `vps.expose.udp` label declares (open to the internet), or a declared port the service does not publish with `mode: host`. |
| <a id="k13"></a>K13 | note | A database that is not exported before each backup: its volume is copied while it runs. |
| <a id="k14"></a>K14 | error | An address another app already holds. |
| <a id="k15"></a>K15 | error | An address that is not under a domain your server serves. |
| <a id="k16"></a>K16 | error | A port that another app already opens on your server. |
| <a id="k17"></a>K17 | error, warning | An `x-catena` block that does not read or does not hold for its file: the server refuses the app's updates. A warning lists the commands it has the server run. |

| Rule | Level | What it reports |
|---|---|---|
| <a id="x1"></a>X1 | error | `privileged: true`. |
| <a id="x2"></a>X2 | error | The server's own network (`network_mode: host`, or the external `host` network). A file of Catena's catalog whose block declares it passes. |
| <a id="x3"></a>X3 | error | `pid: host`, which shows every process of the server. |
| <a id="x4"></a>X4 | error | `ipc: host`, which reaches the shared memory of other processes. |
| <a id="x5"></a>X5 | error | `devices`, which reaches the server's hardware. |
| <a id="x6"></a>X6 | error | The Docker socket mounted in the service. A file of Catena's catalog whose block declares it passes. |
| <a id="x7"></a>X7 | warning | `cap_add`: added capabilities. Keep each only if the app needs it. |
| <a id="x8"></a>X8 | warning | A server folder mounted outside the apps area. |
| <a id="x9"></a>X9 | warning | A port published on the server, reachable without signing in. |

## Troubleshooting

| Symptom | Cause and fix |
|---|---|
| 502 or 503 on the address | The proxy cannot reach the app: the front-door service is not on `catena-network`, or `vps.route.port` is not its port. |
| 403 after signing in | The person is in none of the allowed groups. The group in `vps.auth.groups` exists in Keycloak and matches exactly, letter case included. |
| No route | No `vps.route.host`, or several addresses without exactly one `vps.route.main=true`. |
| Red card on the status page | A public app whose front page answers an error, an app behind sign-in that does not send visitors to sign in, a `vps.health.path` that does not answer 200, or a `vps.health.expect` text absent from the reply. |
| Backup failed | A bind mount outside the apps area, or a failed database dump (step 7). |
| Data missing after a node change | A service with a volume lacked `node.labels.catena.role==data` ([K2](#k2)). |
