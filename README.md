# apps/docs -- docs.catena.run

Astro Starlight site. Public client docs (EN + FR), shared between
docs.catena.run (the public-facing copy) and the on-VPS
`vps-docs.<your-zone>` (the per-installation offline + sovereignty
copy). Same artifact, two delivery paths.

## Develop

```bash
npm install
npm run dev -w @catena/docs
# -> http://localhost:4321
```

## Build

```bash
npm run build -w @catena/docs
# emits apps/docs/dist/  (25 pages -- EN + FR x 12 routes + sitemap + search index)
```

## Release artifact

When the operator tags `docs-v<version>`,
`.github/workflows/docs-release.yml` builds `apps/docs`, packages
the output three ways, and attaches them to a GitHub Release:

  catena-docs-<version>.tar.gz   -- full static site (what the
                                    Ansible vps_docs role downloads)
  catena-docs-<version>.html     -- single-file offline bundle
                                    (every page concatenated)
  catena-docs-<version>.pdf      -- print-friendly PDF

The single-file HTML and PDF are generated by
`apps/docs/scripts/docs-snapshot.mjs` against a locally-served copy of dist/,
using Playwright (chromium) to walk the sitemap + render.

## On-VPS deployment

The Ansible role `automation/ansible/roles/infrastructure/tasks/
vps_docs.yml` has two flows:

- **Artifact** (when `catena_docs_version` is set): download the
  matching tarball from GitHub Releases, extract into
  `vps_docs_host_site_dir`, served by the existing nginx sidecar.
  No Jinja, no per-host customization.
- **Legacy / Jinja**: render `docs/client/src/*.md.j2` per-host with
  Ansible vars + `mkdocs build`. The historical path; default while
  the migration of templated pages -> apps/docs content collection
  is still in flight.

Operators flip an inventory to the artifact path by setting
`CATENA_DOCS_VERSION=0.1.0` (or whichever version) in the
inventory's `.env`. Backwards-compatible: leaving it unset keeps
the old behaviour.

## Adding a page

1. `apps/docs/src/content/docs/en/<slug>.md`,
   `apps/docs/src/content/docs/fr/<slug>.md`.
2. Add the slug to `astro.config.mjs::sidebar` under the right group
   (translation + items list).
3. `npm run build -w @catena/docs` -- catches frontmatter errors,
   broken links, and missing locales.

## Adding a language

Same pattern as @catena/i18n: add a new locale dir under
`src/content/docs/<lang>/` mirroring the EN tree, register it in
`astro.config.mjs::locales`, then mirror every page. Sidebar groups
already declare per-locale `translations` (English + Français
today); add a new entry per group when a third language ships.
